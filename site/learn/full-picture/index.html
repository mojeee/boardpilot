The full picture

One device, one cycle, every lesson

In this lesson

  1. The device is like a body
  2. From your computer to the chip
  3. Interview questions

Follow one cycle of a thermostat. Every embedded device, from a toy to a car, repeats the same pattern: wait, sense, decide, act, sleep.

  1. Power on: the CPU runs the program from flash and sets up pins, buses and timers.
  2. The timer counts by itself while the CPU rests.
  3. The timer raises an interrupt and the scheduler wakes the sensor task.
  4. Over I2C, the MCU asks the sensor for the temperature.
  5. The code compares it with the target and sets one GPIO bit: the heater turns on.
  6. The display task draws the new value on the screen.
  7. A button press raises an interrupt and changes the target.
  8. Everything is done: the CPU sleeps until the next tick.

From your computer to the chip

  1. Write C code in an IDE such as STM32CubeIDE.
  2. The compiler turns it into a binary file.
  3. The programmer on the board (for example ST-LINK) writes the binary into flash. This is flashing.
  4. The MCU restarts and runs your code.
  5. The debugger pauses the chip so you can look at variables and registers, line by line.

In BoardPilot, Flash firmware backs up the board before it writes, and Monitor shows what your code prints.
