RTOS: tanti lavori su un solo chip

Task, priorità e code

Un dispositivo può dover leggere un sensore ogni 10 ms, aggiornare uno schermo lento e inviare dati, tutto insieme. In un semplice ciclo, un lavoro lento fa ritardare gli altri. Un sistema operativo real-time (RTOS) risolve il problema.

Demo interattiva

Ciclo semplice e RTOS. In un ciclo semplice la lettura del sensore aspetta dietro un lento aggiornamento del display e arriva in ritardo. Con un RTOS lo scheduler sceglie per priorità: il task del sensore gira in orario e quello del display viene messo in pausa e ripreso.

Provala nella demo nel browser →

  • Un task è una funzione con un proprio ciclo infinito, come un thread.
  • Lo scheduler esegue il task più importante tra quelli pronti, anche se deve metterne in pausa un altro.
  • Un delay mette a dormire un task, così gli altri possono usare la CPU.
  • Una coda passa i dati in sicurezza da un task all’altro.
  • Un mutex protegge una risorsa condivisa, come la UART, così due task non la usano nello stesso momento.
void SensorTask(void *p) {
    for (;;) {
        float t = read_temperature();
        xQueueSend(tempQueue, &t, 0);          // hand the value to the display task
        vTaskDelay(pdMS_TO_TICKS(10));         // sleep 10 ms, the CPU is free
    }
}

xTaskCreate(SensorTask,  "sensor",  256, NULL, 3, NULL);   // high priority
xTaskCreate(DisplayTask, "display", 256, NULL, 1, NULL);   // low priority
vTaskStartScheduler();                                      // never returns

Real-time non significa veloce. Significa prevedibile: il task importante viene sempre eseguito entro un tempo noto. Lo scheduler stesso è guidato da un interrupt del timer.

Nei prodotti reali

Inversione di priorità: un task a bassa priorità tiene un mutex che serve a un task ad alta priorità, e nel frattempo continua a girare un task di media priorità. Usa mutex con ereditarietà della priorità.
