Che cos’è un microcontrollore?

Il piccolo computer dentro ogni dispositivo

In questa lezione

  1. Microcontrollore o microprocessore?
  2. Tutto è un indirizzo
  3. Che cosa succede all’accensione
  4. Domande da colloquio

Un sistema embedded è un piccolo computer integrato in un dispositivo per fare un solo lavoro: un termostato, una lavatrice, i freni di un’auto. Il suo cuore è un microcontrollore (MCU): un solo chip che contiene un computer intero.

Demo interattiva

Dentro un microcontrollore. Uno schema di un solo chip che contiene un computer intero: il core della CPU esegue il tuo codice, la flash conserva il programma, la RAM tiene le variabili, i timer misurano il tempo con precisione e le periferiche (GPIO, ADC, UART, I2C, SPI) collegano ingressi come un sensore di temperatura e un pulsante a uscite come un LED e un motore.

Provala nella demo nel browser →

Ogni dispositivo segue lo stesso schema: legge gli ingressi, decide nel codice, comanda le uscite.

Microcontrollore o microprocessore?

Microcontrollore (MCU)Microprocessore (MPU)
Sul chipCPU, memoria e perifericheQuasi solo la CPU
MemoriaKilobyteGigabyte
SoftwareIl tuo codice C, o un piccolo RTOSUn sistema operativo completo come Linux
Si avvia inMicrosecondiSecondi
EsempiSTM32, ESP32, ATmegaRaspberry Pi, telefoni, portatili

Tutto è un indirizzo

La CPU vede flash, RAM e hardware come un’unica lunga lista di indirizzi numerati. Leggere una variabile e accendere un LED sono la stessa operazione: scrivere un valore a un indirizzo.

Demo interattiva

Mappa di memoria di un STM32. La flash parte da 0x0800 0000 (qui c’è il main() compilato), la RAM da 0x2000 0000 (variabili e stack) e le periferiche da 0x4000 0000 (GPIO, UART, timer: scrivere 1 nel punto giusto accende il LED).

Provala dal vivo

La vera app, nel tuo browser: questa lezione con la sua anteprima 3D su una scheda ST NUCLEO-F401RE simulata. Niente da installare, niente da collegare.

int counter = 5;                              // the compiler picks an address in RAM

*(volatile uint32_t *)0x40020014 = (1 << 5);  // GPIOA output register: pin PA5 high, LED on

Che cosa succede all’accensione

  1. La CPU legge la tabella dei vettori all’inizio della flash: dove inizia lo stack e dove si trova il codice di avvio.
  2. Il codice di avvio copia in RAM i valori iniziali delle variabili e imposta il clock.
  3. Parte il tuo main(), che non ritorna mai: non c’è un sistema operativo a cui tornare.
