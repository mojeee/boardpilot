## Toolchain decisions

- **Arduino core:** `adafruit:nrf52:pca10056` from the Adafruit board index. The suggested `sandeepmistry:nRF5:PCA10056` does **not** exist: sandeepmistry/arduino-nRF5 `boards.txt` has the nRF52 DK (nRF52832) and nRF52833 boards but no nRF52840 DK. Adafruit's core has a dedicated `pca10056` variant.
- **Caveat:** Adafruit builds link the sketch after the S140 v6.1.1 SoftDevice (`nrf52840_s140_v6.ld`) and its normal upload path is nrfutil through the Adafruit bootloader on the nRF USB port (J3). Flashing only the sketch HEX with nrfjprog works when the SoftDevice (and bootloader) are already on the chip, so the bootloader must be burned once ("Burn Bootloader" uses nrfjprog over the on-board J-Link). The uploadNote says this in plain words.
- `flasher: nrfjprog`, `link: debug-probe`, `imageFormat: hex` as assigned.
- `adcMaxMv: 3600` is the Adafruit core default range; the input itself must still never exceed VDD (3.0 V).

## Estimated / uncertain

- Component body sizes are **estimated** from package names in the pick-and-place file (7 × 7 mm aQFN, 6.2 × 6.3 mm tactile switches, 0603 LEDs, 3215 crystal, micro-USB overhang); positions are exact centres.
- In hardware v3.0.3 the interface MCU (U2) is an nRF5340 running J-Link OB (older DKs used a different chip); the label is kept generic.
- Pin 8 of P1 (Arduino Vin position) is printed "N.C." on the DK and is skipped. In the schematic its net (VIN) only links the top and bottom Arduino footprints.
- P5 (2×3) and the unpopulated through-hole headers P13-P17 and back-side P7-P12 are not modelled; P13-P17 duplicate the Arduino signals.
